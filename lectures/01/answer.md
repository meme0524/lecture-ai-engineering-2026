# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：
  `app.ask` は用語集を検索せず、モデルに直接質問する実装である。そのため、
  講座固有の「宿題の3レベル」については、回答を拒否された。
- 用語集の正しい意味と比べて気づいたこと：
  正しい内容は `data/glossary.json` の `homework-levels` に定義されている。
  素のLLMはこの講座の用語集を参照していないため、講座固有の情報については
  根拠を確認できず、誤った内容を断定する場合がある。外部データを参照する
  ツールや検索機能を追加することが、正確性の改善につながる。
- 表示できたトークン数（入力 / 出力）：
  `response.usage_metadata.prompt_token_count` と
  `response.usage_metadata.candidates_token_count` を使い、それぞれ
  `[入力トークン数]` と `[出力トークン数]` として表示するようにした。
  実際の数値は質問内容、会話履歴、モデルによって変わるため、実行時に表示された
  値を記録する。

## 宿題

- 取り組んだレベル：実装
- やったこと：
  `app/ask.py` を改修し、起動時に `genai.Client` からチャットを1つ作成する
  ようにした。`ask` 関数にチャットを受け取る引数を追加し、`chat.send_message`
  を使って質問を送信することで、同じチャット内の会話履歴を保持できるようにした。
  また、起動後に追加の質問を入力できるループを追加し、`exit`、`quit`、
  `終了` のいずれかを入力すると終了するようにした。空入力は受け付けず、
  EOF が入力された場合も終了する。

  同じ質問「LoRAとはなんですか？」を複数回聞いてみてトークン数を比較した。
- 結果：
　毎度exitを打ちチャットを閉じたうえで再度質問することにした。
　
　使ったモデル：gemini-3.5-flash-lite
　１回目：入力：7, 出力：587
　２回目：入力：7, 出力：602
　３回目：入力：7, 出力：590
　
　次に、会話履歴を保存したまま同じ質問を繰り返してみた。
　1回目：入力：7, 出力：590
　2回目：入力：601, 出力：609
　3回目：入力：1218, 出力：644

- 気づき・疑問：
  会話履歴を保持すると、追加質問で前の文脈を利用できる一方、履歴が長くなるほど
  入力トークン数やコンテキストの消費量が増える。会話を長時間続ける場合は、
  履歴の要約や上限の設定も必要になる。
